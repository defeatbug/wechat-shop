# 设计说明

## 1. 产品目标

给一家饰品小店做「只选款、不发货、不收款」的微信小程序：

- 顾客：像逛团购一样按分类挑款，加进选款清单，填联系方式提交。
- 店主：在「我的订单 → 店主入口」里看订单、推进状态、上下架商品。
- 交易：只做**选款登记**，提交后线下联系确认、线下付款，不走微信支付。

非目标（当前版本不做）：在线支付、物流发货、库存扣减、优惠券、分销。

## 2. 信息架构

```
首页（选款）
 ├─ 顶部封面：店铺头像 + 店名 + 副标题
 ├─ 下单面板：免配送费 / 我的订单
 ├─ 左栏：分类（固定）
 └─ 右栏：商品列表（滚动）
      └─ 加购 → 底部结算条
           └─ 确认选款页（数量 / 联系方式 / 取货方式 / 备注）
                └─ 提交 → 我的订单
                     └─ 店主入口（仅店主）
                          ├─ 订单：待确认 → 已确认 → 已完成
                          └─ 商品：上架 / 下架
```

## 3. 页面与交互

### 3.1 首页（`pages/index`）

- 布局：`flex column` 撑满 100vh；封面 240rpx；面板 `margin-top:-28rpx` 叠出圆角。
- 左右分栏：左 178rpx 固定宽、灰底；右 `flex:1` 白底滚动。
- 分类联动（双向）：
  - 点分类 → `scroll-into-view="cat-{id}"` 跳到对应分组，并短暂锁定 420ms 防止滚动回调抢状态。
  - 滚商品 → `createSelectorQuery` 预先量出每个分组的纵向偏移，滚动节流 80ms 后取「最后一个 offset ≤ scrollTop」的分组高亮。
- 加购：`catchtap` 阻止冒泡，写购物车并 `vibrateShort` 轻反馈。
- 底部结算条：`count > 0` 时 `translateY(0)` 滑入，显示件数与合计。

### 3.2 确认选款（`pages/cart`）

- 清单：缩略图 + 名称 + 单价 + 步进器；减到 0 自动移除。
- 表单：称呼、手机号、微信号（选填）、取货方式（picker）、备注。
- 校验：称呼非空；手机号 `^1\d{10}$`。
- 提交：生成单号 `D{timestamp}`；写入本地或云函数；成功后清空购物车，弹窗提示「线下联系付款」，跳「我的订单」。

### 3.3 我的订单（`pages/orders`）

- 状态映射：`pending 待确认 / confirmed 已确认 / done 已完成 / canceled 已取消`。
- 展示：单号、商品行（名称×数量、小计）、联系人/电话/取货方式、备注、时间、合计。
- 下拉刷新；本地模式顶部提示「订单只存在本机」。

### 3.4 店主后台（`pages/admin`）

- Tab：订单 / 商品。
- 订单：展示全部订单，按钮推进状态（待确认→已确认→已完成）。
- 商品：开关上下架；本地模式写入 `storage` 覆盖层，云模式写 `products` 集合。
- 权限：云函数侧校验 `ADMIN_OPENIDS` 环境变量；本地模式默认放行（演示用）。

## 4. 数据模型

```js
Product {
  _id, catId, name, price /* 分 */, desc, emoji, bg /* 缩略图占位 */, on
}
Category { id, name, emoji? }

Cart { [productId]: qty }

Order {
  _id, no, items: [{ id, name, price, qty }], total, itemCount,
  contactName, contactPhone, contactWechat, pickup, remark,
  status, createdAt /* 毫秒时间戳 */
}
```

云数据库集合：

| 集合 | 权限建议 |
|------|----------|
| `products` | 所有用户可读，仅管理端可写 |
| `orders` | 仅创建者可读写（云函数不受限） |

## 5. 技术选型

- **原生微信小程序**（WXML/WXSS/JS）：无构建步骤，包体小，导入即跑。
- **微信云开发**：免服务器、免域名、免 ICP；单云函数 `shop` 用 `action` 路由，减少部署数量。
- **双模式数据层**（`services/api.js`）：
  - `config.cloudEnv` 为空 → 本地 `storage` 演示模式，任何人 clone 下来都能直接跑。
  - 填了云环境 ID → 走云函数，多人真实下单、订单汇总。
- 价格统一用**分**存储，展示时 `toFixed(2)`，避免浮点误差；0 元商品（福利款/必选礼盒）可正常下单。

## 6. 视觉规范

| 项 | 值 |
|----|----|
| 主色 | `#ff3b30` / `#ff4d4f`（价格、加购、主按钮） |
| 背景 | `#f6f6f6`，卡片 `#fff` |
| 文字 | 标题 `#111`，正文 `#333`，次要 `#999` |
| 圆角 | 面板 28rpx，卡片缩略图 10rpx，按钮 999rpx |
| 字号 | 分类 26rpx，商品名 30rpx，价格 34rpx，标题 32rpx |
| 间距 | 页面左右 22–30rpx，卡片纵向 18–22rpx |

无 `tabBar`，用导航栈；封面/面板的叠层是本项目的视觉特征。

## 7. 目录结构

```
app.*                    入口与全局样式
pages/{index,cart,orders,admin}
services/{api,store,config}
data/products.js         演示商品
cloudfunctions/shop      云函数（catalog/seed/submitOrder/myOrders/listOrders/updateOrderStatus/saveProduct）
scripts/                 结构校验 + 端到端冒烟测试
preview/                 浏览器预览稿（HTML 重画，不参与上线）
```

## 8. 已知限制与后续迭代

1. 商品图目前用 emoji + 渐变占位，上线前替换为实拍图（云存储 + `image` 字段）。
2. 无库存/限量控制；0 元福利款靠人工把关。
3. 「必选商品」目前只是展示，未强制校验。
4. 店主鉴权依赖云函数环境变量，若要多人协作需做角色表。
5. 订单导出、消息通知（订阅消息）、分享海报未做。
